Balcão: triagem automática de pedidos de orçamento para pequenos negócios com API REST e agente no n8n

Henrique Ribeiro Leonardo

Bacharelado em Sistemas de Informação · outubro de 2026

Código-fonte Fluxo do n8n Demonstração Painel

Resumo

Pequenos negócios que vendem por orçamento perdem clientes quando o pedido feito pelo site demora a ser respondido. Este projeto propõe o Balcão, um serviço que fica entre o formulário do site e o dono do negócio. Uma API REST em TypeScript valida e classifica cada pedido por regras explicáveis (serviço, urgência, volume e aderência ao negócio) e o entrega, assinado com HMAC, a um fluxo no n8n. Nesse fluxo, um agente de IA consulta o histórico do cliente pela própria API, define a prioridade e redige a primeira resposta, que chega ao dono pelo Telegram. Pedidos sem resposta no prazo do negócio são cobrados duas vezes ao dia. A implementação não tem dependências de produção e é verificada por 66 testes automatizados.

Palavras-chave: API REST; automação; n8n; agentes de IA; pequenos negócios.

1 Introdução

Oficinas, restaurantes e prestadores de serviço recebem pedidos de orçamento por formulários em seus sites. Na prática, esses pedidos chegam por e-mail a quem está ocupado atendendo no balcão, na cozinha ou na obra, e a resposta pode levar dias. O objetivo do projeto é garantir que todo pedido seja visto, priorizado e respondido dentro de um prazo definido pelo próprio negócio, sem exigir que o dono mude de ferramenta.

Os requisitos definidos foram:

  1. funcionar com o formulário que o site já tem, inclusive sem JavaScript;
  2. classificar o pedido de forma explicável, citando o trecho que motivou cada decisão;
  3. avisar o dono no celular com uma resposta pronta para enviar pelo WhatsApp;
  4. cobrar pedidos parados e medir tempo de resposta e taxa de fechamento;
  5. não registrar dados pessoais em logs e autenticar toda comunicação entre os serviços.

2 Arquitetura

O sistema tem três partes (Figura 1). A API recebe o pedido, aplica a classificação por regras, grava em SQLite e emite o evento lead.created. O fluxo no n8n confere a assinatura do evento, executa o agente de triagem e devolve a decisão à API, também assinada. O painel consome as rotas autenticadas da API para listar, atualizar e medir os pedidos.

3 Classificação por regras

Antes de qualquer modelo de linguagem, a API classifica o pedido com regras determinísticas, rápidas e sem custo (Tabela 1). O texto é normalizado (sem acentos, em minúsculas) apenas para a busca; as justificativas citam o trecho original escrito pelo cliente. O serviço é o de maior número de palavras-chave encontradas, e um serviço escolhido no formulário que não aparece na mensagem é apontado.

Sinal Critério Exemplo

O telefone é normalizado para E.164 com verificação de DDD e do nono dígito, o que permite gerar o link de resposta no WhatsApp. Pedidos idênticos do mesmo telefone em menos de 10 minutos não geram novo registro, e pedidos suspeitos são guardados sem notificar o dono.

4 Agente de triagem no n8n

O nó de triagem é um AI Agent do n8n com o modelo Llama 3.3 (via Groq), duas ferramentas e saída estruturada. As ferramentas são rotas da própria API: historico_do_cliente consulta pedidos anteriores do mesmo telefone, e servicos_do_negocio retorna o que o negócio oferece. A saída contém prioridade, justificativa, resumo e uma primeira mensagem ao cliente. A mensagem do cliente é passada ao agente entre marcadores, com instrução para não seguir comandos contidos nela. Se o agente falhar, o fluxo continua com a triagem por regras.

O arquivo do fluxo é gerado por um script versionado, e os nós de código são executados nos testes contra a API, verificando as assinaturas nos dois sentidos.

5 Demonstração

A API completa foi empacotada para rodar neste navegador, com dados fictícios em memória. Envie um pedido pelo formulário (à esquerda); ele aparece no painel do dono (à direita) e o fluxo do n8n é executado em seguida (Figura 2). Na demonstração, os nós de código do fluxo rodam com o mesmo JavaScript do arquivo importado no n8n e as ferramentas do agente consultam a API; apenas a decisão do modelo é simulada por regras equivalentes ao prompt.

7 Segurança e privacidade

  • Eventos e decisões entre API e n8n são assinados com HMAC-SHA256 e recusados após 5 minutos [1].
  • Rotas do painel exigem token comparado em tempo constante; o formulário só é aceito de sites autorizados.
  • Limite de pedidos por IP, campo-armadilha contra robôs e redirecionamento restrito ao site do negócio.
  • Logs registram apenas rota, status e tempo; o n8n não guarda execuções concluídas.

8 Limitações e trabalhos futuros

  • O fluxo do n8n foi verificado por testes dos nós de código, mas não em uma instância de produção.
  • Na demonstração, a decisão do modelo é simulada; a qualidade das decisões reais ainda não foi avaliada.
  • O SQLite e o limite de requisições em memória atendem a uma única instância do servidor.
  • Como próximos passos: avaliar o agente com pedidos reais anotados e responder pelo WhatsApp Business.

Apêndice A. Integração com um site existente

Basta apontar o formulário para a API com a chave pública do negócio. Com HTML puro, a API redireciona o visitante para a página de agradecimento do próprio site.
